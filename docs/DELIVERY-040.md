# VoxMaster AI 0.4.0 交付与发布门禁

**当前结论：本地候选构建已完成真实处理与 Windows 隔离安装验收；尚未公开发布，不能称为“全部问题已解决”或“专业音质已验收”。**

产品方向：**AI-Powered Vocal Production & Music Mixing Workstation**。本轮沿用现有分析、DSP、模型中心、Studio 与 v1 工程，新增完整歌曲闭环，没有另建混音器、替换音频依赖或引入云端上传。

## 1. 已完成且验证

- 三个显式入口：独立人声、完整歌曲、多轨混音。模式可保存、切换、撤销；不以响度或频谱阈值强行认定素材身份。
- `vox/intelligence.py` 共用旧测量栈，区分原文件规格与内部 44.1 kHz 立体声 PCM；保留未知项与估计说明。
- 完整歌曲经本地固定 Spleeter 双轨、人声保守链、伴奏增益/EQ、现有 Studio 总线、唯一一次最终母带、质量复测、A/B 和编码导出。
- 五种预设混音方向与自定义参数；保守/标准/增强/自定义母带。修改 LUFS 或峰值不再无意改变所选算法力度。目标响度服从峰值和处理预算，不保证所有素材强行达到目标。
- 人声层强制旁通歌曲母带；原始分轨、已调人声、处理后分轨、最终总线保持不同用途，不把原始分轨覆盖成成品。
- 内容 SHA-256 绑定分离来源；替换同尺寸、同修改时间的媒体仍能使旧证据失效。哈希不是模型质量认证。
- 分离发布前失败/取消清理暂存；发布后晚到取消交付已提交结果。分轨目录同时原子发布 `Separated.voxproj`，即使主恢复盘写满仍有引用和精确方案可恢复，失败提示给出路径。主恢复检查点先写入，写入失败不替换当前会话或撤销历史；处理完成前再复核素材身份，拒绝处理期间被外部替换的内容。
- 旧 v1 工程、相对路径、备份、重定位继续可用；外部分轨保留不等长尾音。非中性歌曲处理加真实 Studio 编辑，保存/重开输出逐采样一致。
- CLI `song` 与 GUI 共用服务；输入、成品、权重、模型配置、锁和断点文件受到报告路径冲突保护。源码入口使用 `python app.py --cli song …`，专用控制台使用 `VoxMasterAI-CLI.exe song …`。
- 自动化全量已有 **436 通过、1 跳过、0 失败/错误（437）** 的实际记录，212.3 s；唯一跳过为当前 Windows 账户缺少文件符号链接权限。模型用例实际使用本地固定权重，不用 Mock 替代核心处理。
- 分支推送后 GitHub Actions 四平台（Windows、Ubuntu 24.04、macOS 15、macOS 15 Intel）与 actionlint 作业全部 success（run 44751308841）；这是 runner 上的源码回归，不替代 Windows 10 实机或实体设备验收。
- 两首指定完整歌曲完成真实 DirectML 分离、DSP、FLAC 24-bit 编码和回读，输入不变、帧数一致。最终输出约 −15.00 LUFS-I，真峰值 −6.62 / −6.91 dBTP；这是客观电平结果，不是听感评分。
- 原生 Windows Qt 界面截图已检查，错误数组为空；截图用 CC BY 4.0 FLEURS 语音与合成伴奏，不用用户私有歌曲。

## 2. Windows 发行物与安装生命周期

### 隔离构建

本轮在独立临时构建树冻结与打包，原工作区 `dist` 和现有正式安装未覆盖。冻结收据 `build/frozen-inputs.json` 将应用源码、版本资源和两个 EXE 绑定；最终源码核对无漂移。完整依赖、Qt 对应源码、编解码对应源码与许可证继续随发行材料提供。

供本机验收的最终文件整理在工作区 **`.audit/040-delivery/dist/`**：

| 文件 | 用途 |
|---|---|
| `VoxMasterAI-Setup.exe` | Windows x64 当前用户安装器，未做 Authenticode 签名 |
| `VoxMasterAI-Portable.zip` | 完整 onedir 便携目录，须整体解压 |
| `VoxMasterAI-Source.zip` | 明确范围的源码包，含根 MIT LICENSE；不含私人音频和权重 |
| `Qt-6.12.0-Corresponding-Sources.zip` | Qt 对应源码材料 |
| `SHA256SUMS.txt` | 上述四个文件的实际 SHA-256；以最终重包后的该清单为准 |

包大小与哈希不嵌入源码文档，避免源码包包含自身哈希的循环；最终收拢核验写入同级 `verification.json`。源码包与工作区关键文件逐字节一致，私有指纹扫描零命中；唯一媒体为固定哈希的署名 FLEURS 夹具。这些本地候选文件不是 GitHub 正式发行或受信任的发布者签名。

### 已执行的安装、升级与卸载验收

`scripts/verify-release.ps1 -IsolatedRegistration` 使用唯一 AppId、隔离安装目录、用户数据目录和开始菜单组，避免改动现有生产注册与快捷方式：

1. 校验并使用既有 0.3.2 发行资产；用该版本的安装配方与原便携载荷安装隔离旧版。
2. 旧版实际导入 FLEURS 真人录音，保存设置与恢复工程，再终止仅此次启动的隔离旧进程，模拟异常中断。
3. 升级到 0.4.0；安装后的主 EXE 与候选便携包的 EXE 哈希相同。
4. 安装版与便携版均执行原生 Qt/PortAudio、WAV/MP3/FLAC/AAC 编解码及真实 DirectML 推理自检，均为 **PASS**。
5. 旧恢复工程完整读回 **457,758 帧（10.38 s）**；设置、恢复工程、录音三个文件升级/卸载前后 SHA-256 不变。
6. 隔离卸载 **PASS**；隔离注册和程序删除，用户文件保留；原生产注册和快捷方式未改变。

原始收据位于被忽略的 `build/accept-e98a35fa-09f5-43ee-bc01-31656a003f36/upgrade.json`、`Installed.json` 与 `VoxMasterAI.json`，运行日志 `.audit/040-release-review/installation-final.txt`。**这是隔离 AppId 的真实生命周期验收，不是对用户现有正式安装执行了部署。**

## 3. 已实现但验证不足

- 完整歌曲处理确实运行，但两首指定歌曲没有人工播放、等响盲听、逐项评分或制作人批准。不能宣称人声自然、没有伪影、伴奏无损或“专业母带已验收”。
- 固定 Spleeter 的两轨相加重建误差达到测量下限，源自伴奏采用输入减人声的构造，不是 SDR、串音或知觉音质指标。
- Windows 11 Build 26300 已验证；Windows 10、其他 GPU、实体监听设备热插拔、高 DPI 多屏与低延迟播放缺少本轮实机数据。
- 已有分块推理、解码磁盘映射与 Studio 分块渲染，但完整人声/分轨处理仍占用全长缓冲；没有 >30 分钟音频、连续 100 次任务或资源耗尽的新验收。
- 现有模型中心的校验/暂停/续传能力继续使用，本轮没有新增第二种分离模型或证明所有下载渠道的长期可用性。

## 5. 外部条件与发布门禁

- **人工音质验收未完成**：制作人需等响比较原曲与处理后成品，记录设备、区间、伪影/融合/音色/动态与偏好原因。此项不能靠增加自动化通过数替代。
- **无 Authenticode 签名**：没有提供可信签名证书；EXE 与安装器保持未签名，不能声称 Windows 发布者已验证。Ed25519 更新清单签名是另一机制。本轮 native 暴露面复测仍为 83/C，PE-SIGN 与 PACK-PYI 无新增、无加重，也没有被“修复”。MIT 项目的字节码可提取属于已接受边界，不采用加壳或强制云化。
- **兼容边界**：Windows 10、设备热插拔、CUDA、其他平台/硬件未验收。不能将本机通过扩大为全平台通过。
- **正式发布状态**：当前未创建 v0.4.0 Release、未修改线上 latest 或更新清单。版本标签默认只构建候选 Artifact，稳定公开需从确切 tag 手动选择发布、输入匹配标签并声明听审批准和限制接受；本机已通过 actionlint 1.7.12 和发布保护回归，尚未运行此新流程的远程 Actions。`release` 环境名称不代表已设置审批保护，维护者仍须配置相应保护。发布前需明确接受剩余范围/质量限制并核对确切目标提交、资产与发布说明。若质量门禁未满足，应先作候选验收而不是标成“全部问题修复的正式版”。
- **已修复的发布缺口**：工作流打包后调用隔离安装/卸载验收；签名资产只在全新暂存目录生成并校验，拒绝已有发行目录和残留混入；公开复核须匹配确切版本并下载核验安装包，不能把 CDN 中的旧清单算作新版本成功。公开复核失败不会自动撤回版本，仍需发行人处置。

## 7. 隐私与 Git 边界

没有新增运行依赖、下载模型、上传音频或使用用户歌曲训练。源码归档只允许精确哈希的已署名 FLEURS 夹具，拒绝其他音频与模型。私人逐曲输入、分轨、FLAC、哈希和绝对路径留在被忽略的本机审计材料，不进入公开源码包。`feat/voxmaster-0.4.0` 为独立开发分支；未覆盖稳定工作区发行目录。任何后续推送/发布结果以实际远程回执为准，本文不把准备工作写成已经发布。
