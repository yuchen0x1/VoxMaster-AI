# 导出与启动可靠性迭代

核验日期：2026-11-21。基线为 `main` 的 v0.5.0 发布后源码；本文记录未发行的补丁，不代表新的 Tag、签名更新清单或正式安装包已经公开。

## 能力及本轮改动

VoxMaster AI 是面向喊麦、人声制作和歌曲混音的离线 Qt Widgets 工作站。`vox/interface.py`、`vox/jobs.py` 管理界面与协作取消；`vox/service.py` 衔接分析、可编辑 DSP、隔离的 Spleeter 双轨推理及多轨混音。PyAV 统一到 44.1 kHz 双声道 PCM，PortAudio 负责试听。`.voxproj` v1 是引用外部素材的 JSON，不依赖业务数据库或上传接口。CLI 提供 analyze、tune、song、styles；Windows 用 PyInstaller 和 Inno Setup 构建，另有 Linux/macOS 源码 CI。现有格式、音色、依赖和更新签名规则不变。

| 症状 | 修复与验证 |
|---|---|
| 导出已落盘，尾随取消却提示任务取消 | `PublishedFile` 将已提交的输出交给既有的后台任务成功路径。发布前取消仍不产生文件；发布后显示真实文件路径。测试用真实 WAV 编码、回读及可控的线程同步重现两个分支。 |
| `song` 分轨已落盘，母带无法写入时只输出错误 | 用 `stems` 和 `recovery_project` 返回已保存产物；失败仍以非零码结束，不返回虚假的 `output`。两字段也可随成功结果自动化使用。报告路径校验同时保护恢复工程。 |
| 可选会话标记不可写时，启动中断或退出失败 | 界面启动改为提示数据目录权限问题；若本次启动标记未写入，不会错误关闭上一份标记。关闭时记录诊断错误而不改动 Qt 退出码、工程保存或恢复行为。 |

**整曲失败后恢复：** 在工作站打开结果中的 `recovery_project`，检查分轨后重新导出；清理磁盘空间或换目录即可，无需再次分离。旧调用方仍可用 `error` 和退出码判断成品是否完成。此处不宣称延迟、内存或音质提升。

## 开源比较与取舍

本轮重新获取了以下六个官方仓库的 README/元数据，并参考官方导出手册及已保留的实现/许可文件。未运行竞品、下载模型、复用代码或对速度和音质排名。

| 项目 / 许可 | 已核实设计与 VoxMaster 的区别 | 取舍 |
|---|---|---|
| [Audacity](https://github.com/audacity/audacity) · 发行版 GPLv3，多数源码 GPLv2-or-later | [多文件导出](https://manual.audacityteam.org/man/export_multiple.html)可用音轨或标签划分，默认不覆盖，比 VoxMaster 单次成品导出更通用 | 保留本项目禁止覆盖的承诺，明确实际完成的产物；按区段批量导出留待下一轮。 |
| [Ardour](https://github.com/Ardour/ardour) · GPL v2.0 or later | [导出对话框](https://manual.ardour.org/exporting/export-dialog/)独立设置范围、轨道/总线、格式，可检查编码文件的峰值与响度；会话支持独立快照 | 优先返回已有恢复快照。后续区分内部 PCM 计量与编码文件回读，不引入 DAW 框架。 |
| [Ultimate Vocal Remover GUI](https://github.com/Anjok07/ultimatevocalremovergui) · README 声明 MIT | 面向模型分离的自包含桌面包，按运行环境区分 PyTorch/DirectML/MPS；分离后通常交由别的工作流处理 | 保留固定 ONNX 模型和现有设备回退；独立许可证文件及模型授权未用于本项目代码整合。 |
| [python-audio-separator](https://github.com/nomadkaraoke/python-audio-separator) · MIT | Python API、CLI 批量、多模型及长音频固定分块；其文档说明拼接边界可能有伪影 | 优先验证批项内存生命周期；若增加分块，另做接缝和听审验证，不照搬速度数字。 |
| [Spleeter](https://github.com/deezer/spleeter) · 源码 MIT | TensorFlow 实现支持 2/4/5 轨和 CLI/API；本项目只运行固定 ONNX 双轨转换 | 固定模型版本和权重哈希；代码授权不代替模型及素材授权。不新增大型下载。 |
| [pyloudnorm](https://github.com/csteinmetz1/pyloudnorm) · MIT | 独立 Python 响度计，支持 K 加权/块长/门限和 LRA；不含调音或试听 | 可作未来离线测量对照，不在缺少校准证据时替换本项目的计量。 |

## 测试与发布边界

- 基线 472 通过、1 跳过；新回归在修复前确认 4 个失败分支，保留原用例。最终全量 **477 通过、1 跳过**；文件符号链接用例受 Windows 权限限制。复用校验过的本地权重；未下载新权重。导出、编解码和整曲定向回归 96 项通过。
- Windows 原生 Qt 深浅各捕获 91 个状态、零检查错误，缩放因子 1.25；仅使用公开普通话语音和合成伴奏。静态检查、Python 编译和补丁空白检查通过。这不是人工音质听审、读屏器或实体音频设备验收。
- PyInstaller 冻结程序通过 WAV、FLAC、MP3、AAC 与本地模型验证。安装器、便携包和源码包均本地构建；安装、便携运行、卸载在隔离注册路径通过。深目录安装验收失败两次，移到实际短路径后通过；未测试正式新版覆盖安装，因为本次验证包仍标为 0.5.0。
- **产物禁止公开上传。** 现有源码/便携归档检出未脱敏的本地验收素材元数据；它们不是本轮变更的一部分。必须复核进行中的归档补丁并对最终资产重新扫描。尚无针对新版本的听审、限制接受及正式发布确认。

### 构建产物暴露面

1. **总览：** 对冻结目录扫描 470 个文件、241 个二进制。启发式原始等级 D（0 分）包含依赖误报，不是密码泄露或安全性结论。
2. **发现：** 真实发行边界包括未签名 PE、第三方构建路径及可读的 Python 容器；另有上述源码和便携 ZIP 隐私命中。
3. **证据与处理：** 私钥头命中来自与安装环境原件哈希相同的 Qt 网络 DLL，没有匹配到完整 PEM 私钥块；Token 正则落在与原件哈希相同的 SciPy 扩展内的长标识符中。Qt 通知和 Python 标准库 ZIP 是预期发行文件。该检查不证明产物不存在其他秘密，亦未把系统路径和证据原文公开。
4. **客户端不能解决：** 冻结不是保密机制，客户端只有更新验签公钥，正式签名私钥须留在授权的发布环境。更新清单验签不替代 Authenticode；本项目没有账号计费或客户端订阅判定。
5. **修复顺序：** 先消除并复测实际资产的私有元数据，再核验精确版本与签名更新；Authenticode 和 Win10 实机待单独验收。无需为已公开的 MIT 算法加壳。
