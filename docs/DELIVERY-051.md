## 1. 本轮升级概况

- 项目：VoxMaster AI，本地优先的人声制作、整曲分离与多轨混音工作站。
- 原正式版本：v0.5.0；候选版本：0.5.1。本记录不等于新的正式 Release 已发布。
- 核验时间：2026-11-21，本机 UTC+08；机器是 Windows 11 Build 26300、Python 3.11.18。
- 目标：保留现有功能和工作区成果，修复发行隐私及恢复入口的确定性缺陷，安全整合先前独立完成的导出、文档与淡变维护单元，验证同一音频核心快照。

- `4901ab8` 的工程/素材可靠性、既有暂存的设置取消/归档/隐私/安装配方修复，以及 detached 提交 `c160a7a`、`2dd4538`，均是本次接续整合的已有成果，不冒充本轮新发现或独立重写。

## 3. Bug 修复

| 问题、原因 | 实际修改 | 证据 |
|---|---|---|
| 根内私人目录可通过 Windows junction 别名进入源码 ZIP；Python 3.11 的 `is_symlink()` 不识别该目录重解析点 | `source_archive` 用 `lstat`/reparse 属性识别，`os.walk` 在下降前剪除私有/链接目录；文件、祖先和根 LICENSE 继续检查；无法审阅目录则失败并保留旧归档 | 起始全套中的两个真实 junction 用例失败；修后通过；另测循环、遍历前剪枝及权限失败不替换旧包 |
| `recent=None/int/bool` 或混合列表抛出 TypeError；`stat` 权限/文件消失使整个恢复列表失败 | `recent_paths()` 共用只读类型筛选；按条隔离工程读取/时间戳异常，恢复与历史枚举独立处理 | 新增 10 项修前 8 失败；修后与相邻保存工作流 23 项通过；实际原生窗口恢复成功 |
| 已发布导出遇到尾随取消却显示失败 | `PublishedFile` 明确持久化边界，沿任务成功路径交付真实路径 | 真实 WAV 编码/回读与线程同步回归；发布前取消仍不落盘 |
| 整曲分轨已写入，母带失败却不告知可恢复产物 | CLI 记录分轨/恢复工程，报告路径再次保护恢复工程 | 实际错误 JSON、非零码及恢复路径回归 |
| 多次淡入/淡出只在原节点相乘、再直连端点，可能将整段变为静音 | 原 v1 线性节点格式内对乘积自适应细分，最后一次性替换会话 | 合成 PCM 的相反/同向叠加、局部、JSON 往返、撤销/重做及超限原子性 |
| 安装/便携文档递归带入未审核原始日志 | 明确文档正向清单、六个受管目标的准备/备份/发布与错误回滚；恢复失败保留唯一备份并拒绝带残留重打包 | 真实旧入口隐私哨兵、junction、逐目标故障及最终便携内容检查 |
| 可选会话诊断标记写入失败中断启动或正常退出 | `app.py` 给出诊断权限提示；不把未写入的标记当作本会话成功打开，也不覆盖 Qt 退出码 | 启动/关闭故障注入；本轮原生 GUI 退出码 0、graceful=true |

此前的外部素材 SHA 缓存与提交复核、备份搬迁、模型锁后复核、最近列表非致命写入、更新取消/迟到回调、清单脱敏和安装配方路径规范化均保留并进入全量回归，详见前期记录。没有删除失败测试、放宽安全断言或用异常吞没代替成功。

### 安全暴露面复测

1. **总览**：对真实冻结目录用 package 画像扫描 483 文件、241 二进制、0 Web；启发式零发现。241 项 binary 检查被此画像跳过，不能采纳自动 100/A 当作安全评级。原 native 画像的系统签名/PDB/CFG 及误报解释继续见 [SECURITY-051](SECURITY-051.md)。
2. **发现清单**：`SOURCE-JUNCTION`（P1）根内目录别名入包，已修复并红绿回归；`SHIP-DOCS`（P1）原始证据递归随安装包传播，已用显式清单和实包复核；`SYSTEM-SIGN`（既有发行限制）无 Authenticode，未伪造修复；`PACK-PYI` 为开源可解包边界，不是被入侵证明。
3. **逐项证据与修复**：归档两参数化红灯、遍历/循环/权限测试与实际 ZIP 检查；文档哨兵、逐目标故障/回滚、真实八文件清单。已知私人标识复核仅输出聚合，不公开原始名称/指纹映射。固定公共夹具和对应源码分别保留来源/哈希；不删除许可文件换扫描分数。
4. **客户端无法解决的问题**：MIT 开源源码可读、PyInstaller 可解包是预期。长期私钥和服务凭据必须留在受控发布/服务端，不能靠本地加密或混淆保密。客户端仅需更新验签公钥；验签不能代替主观听审、发布权限和可信 Windows 程序签名。本轮没有新增计费/账号/云端音频接口。
5. **修复顺序**：先保证最终所有资产的隐私和源码身份，再通过远程 main/四平台 CI 与版本专属批准发布；后续补 Authenticode、Win10/实体设备/长音频证据，不降低现有门槛。
