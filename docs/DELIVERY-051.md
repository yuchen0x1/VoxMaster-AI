# VoxMaster AI 0.5.1 交付与发布门禁

**当前结论：0.5.1 是候选版本，不是已公开正式版本。** 本文记录本轮实现、证据和未完成门禁；不能用 0.5.0 的听审或发布批准替代本版本批准。当前官方 Latest 仍为 0.5.0。

## 1. 升级概况

项目仍是本地优先的人声制作、喊麦调音、整曲处理和专业多轨工作站。0.5.1 不改变 DSP、导出规格、`.voxproj` v1 工程、模型格式或运行依赖，集中修复三个会影响结果可信度的边界：外部时间线素材身份、已发布导出的取消语义、多轨缺失素材恢复生命周期。

本轮还收紧了发行输入：公开语料清单不再携带私人文件名；本机私有文件名映射和私有 SHA-256 仍只留在被忽略的本地审计目录；源码包与随包文档不能从工作树混入未跟踪的本地记录。

## 2. 新功能与兼容修复

- 外部多轨素材纳入统一路径签名、SHA-256 和提交前复核。同大小、同修改时间替换会重新解码；处理中被修改或删除的素材拒绝提交并保留旧会话。
- `audioio.encode()` 返回不可变提交回执。提交前取消仍清理临时文件；Windows 使用不覆盖的重命名，POSIX 使用不覆盖的硬链接发布；已有目标始终不覆盖。
- 发布后临时文件清理失败不再伪装成取消或失败，GUI、CLI 与歌曲审计显示“已保存 + 清理警告”。
- 多轨恢复可在当前窗口点击“重新定位素材”重试。已选候选保留；损坏或过短候选可以重新选择；完整恢复前不能应用占位会话；关闭窗口不会启动排队恢复。
- 历史本地语料验收工具增加显式私有文件映射入口。映射不生成指纹、不覆盖公共夹具、仍要求外部提供原始 SHA-256。

## 3. Bug 修复

本轮先用故障注入回归复现，再修复并保留回归：

1. 外部源同大小同 mtime 替换时旧缓存未失效；现以内容哈希参与复用条件。
2. 外部源在渲染接近提交时删除或替换仍可能发布失效工程；现由最终媒体检查拒绝提交。
3. 编码文件已经发布后晚到取消可能被 Worker/UI 误报为取消；现以提交回执区分已发布结果和可取消草稿。
4. 发布成功后的临时文件清理异常可能吞掉成功结果；现交付回执并保留警告。
5. 多轨重定位取消、读取异常、损坏候选和过短候选后无法在当前窗口恢复；现支持重试和重新选取。
6. 排队恢复在窗口关闭后可能继续打开文件选择器；现以关闭状态和 Future 生命周期共同阻止。

## 4. 性能与架构

- 外部媒体内容哈希增加一次与文件大小成正比的读取，以换取缓存/重开一致性；本轮不宣称提速。
- 仍使用现有 Session 交换、事件取消、线程池和事务式工程提交；失败不替换当前会话。
- 没有新增数据库、云端服务、远程上传、模型下载或不可逆数据迁移。
- 长音频全链路恒定内存、插件/VST3、第二种分离模型和更强语义模型不是本轮交付。

## 5. UI/UX

源码 Qt 工作站使用授权 FLEURS 普通话夹具进行了原生 Windows 操作：加载、AI 一键调音、等待“成品已就绪”、打开导出对话框并导出，随后窗口退出。AX 状态确认了测量、成品状态、导出入口及恢复相关控件；本次未进行实体监听或主观听审。

原生导出对话框将测试成品写入了用户 Music 目录，而不是预期的本轮隔离证据目录；应用没有覆盖既有目标，当前该成品不作为发行资产，也不进入源码包。后续应把原生 UI 文件对话框路径操作纳入独立隔离目录验收。

本轮未新增 Windows 10、混合 DPI 实体多屏、实体设备拔插、完整屏幕阅读器或 Authenticode 验收。

## 6. 开源研究

`docs/RESEARCH-051.md` 固定记录六个官方仓库提交 SHA、活动时间、许可证、源码链接和本轮可借鉴/不采用的边界：Audacity、Mixxx、Ardour、Ultimate Vocal Remover GUI、Demucs、Spleeter。研究是官方源码和文档静态比较，不是竞品性能或音质实测；没有复制第三方代码，也没有增加第三方运行依赖。许可证声明不等于完整授权链，尤其不把缺少固定提交 LICENSE 正文的仓库当作可直接复制来源。

## 7. 测试与实测证据

本轮证据目录为被忽略的本地审计目录；原始 XML、日志、模型缓存和私有映射不应进入发行物。

- 初始基线：469 个 testcase，459 通过、10 跳过、0 失败/错误；跳过为模型权重门槛和 Windows 符号链接权限限制。
- 真实本地模型基线：72/72 通过。
- 最终全量：528 个 testcase，527 通过、1 跳过、0 失败、0 错误；使用本机固定 ONNX 权重，不以 Mock 替代核心分离。唯一跳过仍为 Windows 账户缺少文件符号链接权限。
- 发行与语料隐私针对性回归：35/35 通过；覆盖中性语料 ID、显式私有映射、旧报告续跑拒绝、Git 暂存快照、未跟踪文档排除、查询失败不回退、树内/树外联接、目标 staging 联接和大小写变体。
- `ruff` F/E402 规则、Python `compileall`、PowerShell 语法、`git diff --check` 已通过（Git 对若干 LF 文件给出将来转换 CRLF 的提示，不是测试失败）。
- PyInstaller Freeze、Package、便携包自检和当前版本隔离安装/运行/卸载均通过；WAV/MP3/FLAC/AAC 编码与回读自检通过。
- 最终源码包含 253 个文件，文本成员旧私有文件名、用户绝对路径和 hostname 命中均为 0；不含 `.audit` 或本机映射。便携包含 852 个成员，不含审计目录或私有映射；第三方 FFmpeg 构建说明仍保留非私人的工具链配置路径，不能据此宣称包内没有任何绝对路径。

最终候选的四项资产及准确 SHA-256 只记录在同目录 `SHA256SUMS.txt` 和本机审计收据中，不嵌入源码包文档，避免发行物对自身哈希形成循环。

测试失败、跳过、无法执行的部分均按原始 XML 记录，不通过删除用例、跳过测试或降低门槛制造通过假象。

## 9. 发布门禁

正式发布仍需要：

1. 四平台 CI 和 actionlint 以准确提交 SHA 通过；不能把本机测试冒充云端 runner 结果。
2. 制作人对 **0.5.1** 完成当前版本人工等响听审，并明确接受本文限制。自动任务、代理报告和 0.5.0 批准都不构成该确认。
3. 发布技能要求的准确 tag SHA、标题、notes、资产哈希和最终确认齐备后，才可创建正式 Release。Tag/候选构建不等于正式公开。

当前版本隔离安装、便携运行、0.5.0→0.5.1 升级、项目恢复和卸载均已通过；上一版 Setup、Portable 和 Source 资产均先按公开 `SHA256SUMS.txt` 核对，再用于隔离验收。

Authenticode 签名和自动安装回滚仍未实现；没有证书时不伪造签名或购买外部服务。

最终逆向暴露面扫描也保留真实边界：package profile 扫描 568 个文件和 241 个二进制，启发式结果为 100/A，但二进制检查跳过，不能当作完整安全证明；native profile 为 83/C，明确命中未签名和 PyInstaller 可解包边界。扫描器自身合成自检为 58/60，两个与 ELF/APK 识别有关的自检失败，未把扫描器结果包装成零风险。
