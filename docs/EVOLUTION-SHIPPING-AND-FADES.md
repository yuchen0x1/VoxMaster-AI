## 3. Bug 修复

### SHIP-DOCS：原始证据随安装包传播

原 `packaging/stage.py` 递归收集 `docs` 下 Markdown、PNG、JSON、JSONL、CSV、TXT；源码 ZIP 的过滤规则不约束这条管线。内部日志和开发机路径因而可能进入安装/便携负载。

改为 `packaging/shipping_docs.py` 明确文档清单，未知文件默认不加入；重新 staging 时替换旧 docs，避免旧证据残留。`MULTITRACK.md` 保留原有验收数字但将一个私人素材标题换为中性编号，不公开真实曲名。

安全与事务边界：

1. 必需源文件及其父链必须为根内普通文件，拒绝 symlink/junction；目的目录父链同样检查 Windows reparse point，兼容 Python 3.11。
2. 全部内容先准备，六个受管目标（docs、README、LICENSE、CHANGELOG、两份 ThirdParty 说明）统一备份、发布，文件系统错误时回滚；不替换整个第三方许可目录。
3. 恢复副本放在递归打包目录外；回滚本身失败则保留唯一旧副本，不删除以伪装成功。发现未处理的旧备份时拒绝下一次打包，避免残留证据重新进入发行物。
4. 仅管理构建 staging，不迁移或覆盖用户工程/素材。不是应对任意恶意并发写者的安全沙盒，也不是内容 DLP；允许的手册/截图仍须人工审核。当前链接转换只覆盖所选手册的简单行内 Markdown 链接，不是通用 Markdown 清洗器；带 title、引用式、HTML/autolink 等写法需另行检查。

红灯：真实旧入口会带入 `docs/private.json` 哨兵。新增回归覆盖未知扩展名/Markdown/图片、旧 staging、缺少必需手册、每一受管目标发布失败、回滚失败重试、真实 Windows 源/目标/父级 junction、离线链接、许可证保留及幂等重跑。

### FADE-PRODUCT：叠加淡入淡出使选区静音

原 `Session.fade` 只在已有包络节点和端点计算乘积，再线性连接。线性包络与线性淡变相乘一般为二次曲线；1001 帧、振幅 0.2 的常量素材先全段淡入再淡出，会保存为两个零节点，整段成品变静音。两次淡入的中点也错误地保持 0.1，而不是 0.05。

修复在每个原线性区间自适应加入整数帧节点，以实际采样中点误差控制细分，保留 `.voxproj`/Studio schema=1 的既有线性包络格式。本次乘积近似的包络增益绝对误差上限为 `1e-5`，不是无限次编辑累计误差保证；每片段本次最多新增 4096 节点，不含既有节点，也不是整个选区的总预算。超限在替换会话前明确拒绝，保留全部片段、撤销和重做历史。不是每采样一个节点，不修改源 PCM。

红灯为 5 项中 4 项失败；修复后相反/同向叠加、已有节点、局部区间外不变、源 PCM 不变、撤销/重做、JSON 往返及长逻辑区间节点有界等回归通过。振幅 0.2 的反向叠加中点恢复为 0.05；这属于编辑正确性，不是主观音质评价。另补复杂度拒绝的原子性测试。

## 4. 性能与架构优化

- 没有更换音频引擎、模型、编解码规范、公开接口或工程 schema。
- 淡变细分以线性区间为单位、整数帧二分，采用显式误差与节点预算；长区间测试人为将片段终点扩到源 PCM 之外，只验证细分算法的节点增长，不代表合法长工程的渲染、内存或吞吐验收。
- 文档 staging 只依赖 Python 标准库，平台无关的选择/链接逻辑可直接测试；Windows 编解码和许可证准备仍留在原 stage 入口。

目标是 `github.com/yuchen0x1/VoxMaster-AI` 的 main。远程保护要求 PR 和 Windows/Ubuntu/macOS ARM/macOS Intel 四个平台检查，不能直接绕过。仅在确需通过保护规则时使用一个短期审查分支，验证并合并后删除自己创建的临时远程分支；不清理既有他人分支。

最终只读复查时，远程 main 仍为上述 `f0c2afa`，无开放 PR；Latest Release 仍为 v0.5.0。本轮仅固化独立本地提交，最终 SHA 以交付消息和该 worktree HEAD 为准，不推送、不创建 PR、不合并、不创建 Tag 或上传资产。远程写工作流要求展示具体提交/操作后的明确确认，本轮没有据此执行远程写入；不把其他会话或自动通知当用户确认。共享脏工作区和 0.5.1 发布权保持不变。

## 9. 版本发布边界

本轮没有复用 v0.5.0 的人工批准，没有将 `listening_approved` 填成虚假事实。正式新 Tag/Release 仍需：安全集成原有 0.5.1、版本一致性、准确资产重建、全部必需检查、准确旧版升级、本版本制作人听审与限制确认。本地构建成功不等于新版本公开发布；未验证的源码/安装资产不上传为稳定版。
