# 0.1.1 持续播放、渲染与导出压力

2026-11-18 在 Windows 11 x64 本机运行，使用 FLEURS 10.38 秒真人普通话及程序生成的伴奏。每一轮使用真实 PortAudio 输出流（监听音量设为零），后台轮换 18 种风格、混音、切换播放缓存，将成品写入 WAV 并重新解码，检查帧数、声道和有限值。测试临时目录独立，输出写入后立即校验和清理。运行中的 Python 进程记录实际载入的源码快照、墙钟时间、进程 CPU 时间、工作集、私有提交量、句柄数、整卡 GPU 利用率与显存，以及音频回调欠载。原始日志每行刷写至磁盘。[压力脚本](../scripts/soak.py)

## 故障复现与复测

首次在 Windows 默认输出端点运行，208.109 秒后播放缓存替换失败，此前已完成 559 轮。最后记录到的回调欠载为零。初始设备表含 OnePlus 蓝牙耳机，此后新进程枚举只剩板载声卡。测试缺少设备操作时间记录，无法确认两件事的因果关系。传输现在可以在回调停止或异常结束时重新枚举并尝试默认输出，恢复循环区间和游标。如果默认输出也持续中断，会停播并报告错误。复测将实际连续负载固定到 Senary 板载输出，另以故障注入检验断连处理。[首次失败的原始记录](evidence-011/soak.jsonl) · [设备故障测试](../tests/test_compatibility_011.py)

## 复测

从 `hardware.devices()` 或设置页确认输出端点；下列示例的编号 3 仅对应本机此次板载 MME 端点。省略 `--device` 会使用 Windows 默认输出。脚本拒绝覆盖已有日志。

```powershell
.\.venv\Scripts\python.exe scripts/soak.py build/soak.jsonl --minutes 20 --device 3
.\.venv\Scripts\python.exe scripts/soak.py build/application-soak.jsonl --minutes 8 --device 3 --application
.\.venv\Scripts\python.exe scripts/probe_host.py large build/large-wav.json
.\.venv\Scripts\python.exe -m pytest -q tests/test_audioio.py tests/test_workstation_devices.py tests/test_compatibility_011.py
```

专项设备、文件与恢复回归共 38 项通过。人工监听、过夜或 24 小时运行、所有设备驱动和满盘写入仍有不同验证条件，现有数据不能推算这些环境里的故障率。CPU 使用量可按「进程 CPU 秒 / 墙钟秒」换算为等价占用的逻辑核心数；例如 1.0 表示一个核心持续忙碌。本机为 32 逻辑线程。整卡 GPU 计数含桌面及其他进程，只有模型专项日志中的 DXGI 读数可归因于本应用推理进程。
