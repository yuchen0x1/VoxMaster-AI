# 官方更新与数据保护

在「设备与设置 → 软件更新」打开官方更新窗口。手动检查不会在下次启动反复提醒。窗口展示当前/新版本、发布日期及更新说明；确认后下载，显示实际进度与平均速度。关闭窗口会请求取消，并等待更新任务结束。网络请求设有连接和读取超时，并非整个任务的总时限。

客户端读取本仓库 `releases/latest/download/update.json` 和 `.sig`。内置 Ed25519 公钥验证清单原始字节，再校验 schema、最低客户端版本、平台资产、完整 URL、包大小和 SHA-256。只接受 HTTPS，本仓库 Releases 和 GitHub 资产 CDN；拒绝跳转到其他站点。下载写独立临时文件，长度/哈希均符合后原子提交。提交前取消或失败会清理临时文件，原工程与当前程序不变；提交完成后关闭窗口会保留安装包。重新打开并检查更新时，只有缓存文件与新验签的官方更新资产大小及 SHA-256 一致，才可直接使用。安装前再计算一次散列，且始终需要手动确认。

Windows x64 下载完成后可启动验证过的交互式 Inno 安装器。请先保存工程，安装器提示关闭程序后再继续，安装完成可重新启动。本轮没有实现自动安装、自动重启健康检查或自动失败回滚。便携用户不要覆盖运行中的目录：下载官方 ZIP，校验后解压到新目录，保留上一版。所有版本默认共享原有用户数据目录。

自 0.3.0 起程序在本机数据目录写入 `session-state.json` 会话标记：正常退出标记 graceful，异常退出或断电后下次启动显示温和提示（含上次版本号）。这是本地诊断记录，不上传任何数据；更新后首次出现异常提示可作为反馈依据，但不能替代安装后的完整验收。

Linux/macOS 本轮为源码试验支持：保留旧虚拟环境，新版本建立新环境、安装锁定依赖、用副本工程验收后切换；失败切回旧环境。没有 DMG/DEB/RPM 的自动替换功能。不要把源码更新描述为原生安装器更新。

## 尚未验证与恢复

传输签名不是 Authenticode 或 Gatekeeper。没有系统签名证书时会出现系统提示。自动回滚、安装中断、重启及跨真实操作系统升级需专项验收，不能由下载测试推断。旧版 0.1.1 没有官方安装更新入口，首次需手工下载新版。

更新缓存默认在用户数据目录 `updates/`，不会包含录音。设置和恢复工程位于同一用户数据目录，其模式不变。更新前保存 `.voxproj` 和素材备份；工程历史仍由原工程保存逻辑产生。回退旧程序不会自动回退新版本编辑过的工程。

## 发布者

私钥在开发者工作区外受 ACL 保护，并使用 GitHub release 环境 Secret `UPDATE_SIGNING_KEY` 注入签名步骤。`scripts/release_assets.py` 签名后立即用客户端公钥验签，错误 Secret 会阻止发布。没有密钥不能生成可信更新；SHA256SUMS 只用于完整性检查。

密钥泄露时按 SECURITY.md 停止发布并通过独立渠道分发新客户端。本轮尚未建立离线恢复密钥或多方发布审批，维护者应自行备份密钥，不要把备份提交到仓库。
