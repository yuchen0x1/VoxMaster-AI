## 验证结果

最终集成回归命令：

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
.\.venv\Scripts\python.exe -X faulthandler -m pytest tests -q -o faulthandler_timeout=30 --junitxml=build/bugfix-tests.xml
```

- 进程退出码：**0**。
- 按最终 JUnit 的独立 `testcase` 节点统计：**186 个用例，183 通过、3 跳过、0 失败、0 错误**。用例总数相较审计基线增加 56 个；其中新增一个用例因系统权限限制跳过。
- 最终集成用时约 **42.80 秒**。本地 JUnit 可用上述命令重新生成。统计以可逐条核对的独立 testcase 节点为准，不与 XML 顶层聚合数混用。
- CI 同口径 Ruff（`--select F --ignore F841`）及新增/修改回归文件的同口径检查：通过。
- 源码与脚本语法编译、版本一致性脚本、`git diff --check`：通过。
- 原有录音导入、调音、A/B、保存重开、导出、多轨和参考试听等既有回归均通过。

针对性证据包括：

1. 真实子进程分别运行成功断言、失败断言、收集异常、零用例及错误参数，退出码依次为 `0/1/2/5/4`。
2. CLI 使用临时录音副本验证同路径、批处理中后续输入、计划输出、硬链接、Windows 大小写别名，以及尚未生成输出的跨平台大小写/Unicode 归一化别名的拒绝；模拟原子发布失败时，旧报告及输入保持完整。
3. 临时本地 bare 仓库验证匹配 SHA 时可删除，远程分支新增提交后旧 SHA 的删除租约被拒绝且新 tip 保留。
4. 设置窗口连续打开关闭后不再保留隐藏实例；效果器关闭并清空会话引用后，旧音频弱引用可释放；参数结果在销毁前被正确读取；结果处理抛出异常时窗口仍清理。
5. 新目录、正常关闭后的下一次启动、异常会话后的启动分别得到正确提示。
6. 优化模式运行损坏图标的包验证，返回 `FAIL` 与退出码 `1`。

## 跳过项与交付边界

三项跳过均明确记录在 JUnit：

- `test_real_speech_with_known_instrumental`：未提供 `VOX_MODEL_TEST_WEIGHTS`。
- `test_recover_active_gpu_worker_exit`：缺少本地双轨模型权重。
- `test_report_rejects_symbolic_link_alias`：当前 Windows 进程没有创建文件符号链接所需权限。未请求提权；硬链接别名和 Windows 大小写路径保护已实际通过。

本轮验证不等同真实权重下的完整 GPU/CPU 分离、Windows 10 实机、实体设备热插拔、长时间真实监听或安装器升级验收。本记录覆盖源码与回归验证；0.3.2 二进制资产的构建及发布状态以正式 Release 流水线为准。
