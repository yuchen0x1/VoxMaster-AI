# 0.4.0 性能实测与比较口径

本轮不声称“提升 X 倍”。原路径没有完整歌曲闭环，不能把旧版直接对整曲套人声链的耗时，与新版分离+分别处理+混合+母带的耗时作加速比。

## 已测

| 工作负载 | 本机 | 完成耗时 | 口径 |
|---|---|---:|---|
| 月色倒映在西湖（104.882 s）整曲闭环 | RTX 5060 Laptop / DirectML | 首测 21.842 s，最终复测 18.620 s | CLI 进程启动→输出 FLAC 24-bit→回读测量，含模型加载 |
| 寒冬向北（117.070 s）整曲闭环 | 同上 | 首测 23.049 s，最终复测 20.574 s | 同上；两次样本不足以给出加速比 |
| 0.4 基线全测试（190 用例） | CPU，模型用例跳过 | 61.678 s | pytest JUnit wall time；非音频性能比较 |
| 0.4 首次全测试（358 用例） | CPU + 真实 DirectML 模型恢复用例 | 124.479 s | 355 通过、3 跳过；增加用例不可直接比作性能回退 |
| 0.4 最终全测试（418 用例） | CPU + DirectML + 真实 CPU 歌曲链路 | 170.179 s | 417 通过、1 权限跳过；测试拓扑和工作负载不同，不作引擎加速比 |

整曲处理时未记录系统峰值 RSS、显存或 CPU 占用曲线；不能据此声称内存优化或 GPU 调度改进。声学指标和输入不变核验见 [AUDIO-040.md](AUDIO-040.md)。

## 已有代码与新层的开销边界

`audioio` 对大解码使用磁盘映射；`studio_session` 分块渲染且检查总缓冲预算；`models_runtime` 分块 STFT/ONNX/交叉淡化。新歌曲层在改动 EQ 后复用自己拥有的数组作增益，零改动返回原数组，减少多余副本。人声与伴奏本身仍需完整缓冲，**不等于流式全链路**。

未覆盖：>30 分钟长音频、连续 100 次处理、磁盘不足、显存耗尽、实体设备热插拔。后续应按固定素材、固定参数、进程环境、冷/热模型两种状态采样 wall time / RSS / GPU peak，至少重复 3 次再报告分位数。
