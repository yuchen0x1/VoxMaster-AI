# VoxMaster AI 0.4.0 升级方案与候选清单

**初始基线：**`36b4520`（在 `v0.3.2` 之后，应用版本仍为 0.3.2）。下文「基线」只描述该提交的源码及已有文档；「选入」表示计划范围，不表示已实现、已验收或已发布。旧版实测只作回归参照，不作为 0.4.0 通过证据。

## 本轮范围与路由契约

本轮复用已有分析、分离、DSP、多轨与工程服务。增加一套可共享的测量和证据结构，显式区分**观测、推测和未知**：报告注明对象（原音、哪条分轨、总线、编码成品）、采样口径、分析区间与限制；缺失、静音、低置信或证据冲突用 `unknown`（并给出原因），不能把门限占位值当实测数值。F0、起音密度、声道宽度等只作提示，**不自动决定路由**。不引入新模型、运行时依赖、联网推理或上传。

| 显式路由 | 输入与动作 | 未满足条件时 |
|---|---|---|
| **独立人声** | 用户确认单独人声或指定 Vocal；复用现有一键调音、参数编辑与等响 A/B。仅处理选定人声，不调用分离器。 | 疑似混音只提示重新选择；不能把既有 `Vocal` 槽中的整曲默认当作干声。 |
| **完整歌曲智能混音** | 用户选择整曲；复用来源关联明确且已对齐的 Vocal / Instrumental，或由用户明确触发既有 Spleeter 双轨分离。分别测量和保守处理两轨，按相同时间窗自适应平衡，最后在混音总线做一次母带。 | 无有效双轨且权重缺失或校验失败时，提示使用模型中心或提供可用双轨；不后台下载、不将整曲送入人声链。取消、分离或渲染失败保留上一次可用状态。 |
| **多轨专业工作站** | 沿用现有时间轴、编辑、轨道/总线效果器和手动平衡；可以检查整曲处理结果，但进入工作站不自动触发分离、应用建议或重置编排。 | 待应用的整曲方案与手动编排冲突时，先提示并由用户选择；不静默覆盖片段或叠加第二次母带。 |

**处理边界。** 原素材只读；工作 PCM 继续使用 44.1 kHz 双声道浮点。只对有证据的分轨做有界处理：人声以高通、均衡、去齿、动态控制为主；降噪和空间效果按证据及用户目标限制力度，整曲路径不默认强制改音高。伴奏使用有限电平调整及必要的轻量均衡，不套用人声预设；两轨同时活动且存在掩蔽证据时，才可启用有上限的避让。总线按输入响度、动态和余量调整；遇到响度目标与真峰值上限冲突，优先守住峰值并报告差距，不承诺每段都能达到目标。参数、旁通原因和实测结果可查；试听增益不写入导出。

**工程兼容。** 维持 `.voxproj` 外层 `version=1`、既有相对路径、备份及重定位语义。新增路由、分轨来源及已采用的有界参数/测量摘要放在可选、独立版本化的 JSON 字段；保存的是可重放的决定而非 PCM、仅供显示的类型标签或一次性缓存。字段缺省走旧路径，不因打开旧工程自动分离或重新母带；损坏、未知版本或素材失配明确提示，不覆盖原工程。目标是新版读取并复现旧工程，不承诺旧应用能执行新方案。

## 验收门槛

- **G1 路由与证据：**用独立人声、已知双轨混合、纯伴奏、静音/短段、左右反相和易混淆人声样本覆盖显式选择、`unknown`、手工改选及旁通。旧版标签若兼容保留，仅作参考。固定输入下结果稳定；不从 BPM/F0 单项推出声源身份、真假嗓、曲风或情绪。
- **G2 分离和渲染：**核验输入、分轨、成品的帧数、声道、对齐和有限性。针对同源 Spleeter 双轨，在受控夹具上验证无处理相加恢复原混音（建议最大绝对误差 `1e-6`）；这只证明重建，不代表没有串音。检查缺权重、哈希错误、取消、GPU 失败及 CPU 回退；仅用已有合法本地权重，权重缺失则记录真实模型用例跳过。验证分轨处理只影响目标轨、无重叠活动窗不触发避让、不同输入得到不同有界增益，母带只应用一次。记录前后 LUFS-I、采样峰值、四倍过采样真峰值及近满幅计数；对内部混音可沿用现有 `ceiling + 0.025 dB` 回归容差，编码成品另行实测，不套用总线读数。
- **G3 非破坏与兼容：**比较同基线的旧人声工程和旧多轨工程；新方案保存/重开、另存、备份恢复和素材重定位后，用相同素材与环境重放并比对 PCM。取消、坏字段、缺轨、编码失败、目标路径已存在时，确认输入和上次成功会话不变，无可误认的半成品。
- **G4 客观与听审分开：**自动回归使用[有署名的真人普通话夹具](../tests/fixtures/README.md)及可重建的合成伴奏，保存输入、参数、区间、环境、失败和实际 provider。对导出文件按实际采样率/声道回读，至少以无损夹具独立交叉核对响度和真峰；有损编码的峰值变化另报，不自动改写成品。真人整曲、分离串音和主观质感用有授权素材、相同区间的等响盲听验证，参考[旧版方法](LISTENING-011.md)。拿不到合法素材、已知真值或审听者时标「未测/质量阻塞」，不能用合成通过代替真实听感，也不能以较响作为更好。
- **G5 集成回归：**先保留基线结果，再运行全部测试及新增路由、模型、保存、导出和 Qt 交互用例；报告通过、失败、跳过及原因，保持 CLI 原退出码和不覆盖行为。离屏 GUI、模拟设备和已往 Windows 记录不代替实体声卡热插拔或 Win10 验收。

候选优先级为 **P0**（当前安全链路及发布门槛）、**P1**（有直接用户价值，按范围选入或后续排期）、**P2**（验证或研究后再排期）。难度为低/中/高，相对于现有工程。每项的范围决定与基线现状分别标注；「沿用回归」不算新增功能，「质量阻塞」不影响完成有证据的基础子集，但阻止对应的质量声明。

## A · 信号测量与识别（01–10）

### 01. 爆发音识别
- **基线／问题：**`analysis.analyze` 统计 20 ms 强声跃升，`acoustics` 有瞬态候选，`segments` 有「强爆发音」；鼓点、爆破辅音与削波均可产生相近信号。
- **方案／模块：**选入共享起音时间、相对电平和证据来源；优先从 Vocal 取证，整曲仅标瞬态，不确认为人声爆破。`analysis.py`、`acoustics.py`、`segments.py`、`service.py`。
- **优先级／难度／风险／收益：**P1／中／误判会吃掉鼓点或咬字／可快速定位并保护峰头。
- **验收：**分别输入已知起音、干声爆破和鼓点混音，核对时间并在声源不明时返回未知；不因单个起音自动强降增益（G1）。

### 02. 拖腔识别
- **基线／问题：**分段已有拖腔与稳定 F0 线索，声学报告有最长稳定段；长乐器音、双人和声也可满足阈值。
- **方案／模块：**选入稳定音高时长、连续性与可信区间；只对明确人声给拖腔候选，冲突时不驱动音高修正。`analysis.py`、`acoustics.py`、`segments.py`、`pitch.py`。
- **优先级／难度／风险／收益：**P1／中／误识别会处理自然颤音或乐器／便于保留持续音质感。
- **验收：**稳定长音有候选、短音与静音不触发；同长度的纯乐器不被确认为人声拖腔（G1）。

### 03. 真假嗓特征分析
- **基线／问题：**有 F0、置信度、频谱和动态，没有声区识别器；[历史素材](AUDIO-011.md)缺同一演唱者的可靠真假嗓转换标注。
- **方案／模块：**质量阻塞。仅共享可测 F0、稳定性与频带证据；真假嗓结论保持未知。未来需可授权的同人、同句、同条件标注及跨歌手评估。`analysis.py`、`segments.py`、`tests/mc_corpus/`。
- **优先级／难度／风险／收益：**P2／高／音高、距离和麦克风会混淆声区／有真值后才可辅助声区过渡处理。
- **验收：**本轮不输出真假嗓标签或专属处理；解阻需独立标注测试集、误判与拒判统计及未见歌手复核。

### 04. 快速咬字识别
- **基线／问题：**`segments` 用局部起音密度和有声占比给候选；起音并不等于音节，伴奏鼓点容易抬高密度。
- **方案／模块：**选入以 Vocal 为优先的每秒起音和置信证据，混音只显示起音密度，不将其解释成实际语速或吐字准确度。`segments.py`、`acoustics.py`、`review.py`。
- **优先级／难度／风险／收益：**P1／中／把鼓点当咬字会过度去齿或压缩／帮助定位需要保留的辅音。
- **验收：**快/慢受控人声的密度方向正确；无可靠 Vocal 的节拍密集样本不输出确定语速，低证据不增强处理（G1）。

### 05. 句尾延音识别
- **基线／问题：**`tail011.phrase_boundaries` 已找持续发声后的停顿，带尾音编辑及下句保护；自然降声、混响和鼓尾仍难区分。
- **方案／模块：**选入复用有声到停顿的证据及可编辑发送点；不确定时不自动添加明显空间效果，不越下一句或工程边界。`tail011.py`、`pitch_tail_editor.py`、`engine.py`；见 [PITCH-TAIL-011](PITCH-TAIL-011.md)。
- **优先级／难度／风险／收益：**P1／中／拖尾吞下一字／保留自然句尾并方便试听。
- **验收：**长发声后停顿有候选；无停顿或只有伴奏时不生成确认的人声尾音；下一句起音及范围外干声按旧回归保护（G1/G2）。

### 06. 喊麦和唱腔分类
- **基线／问题：**整轨与分段已有启发式标签、证据和手工覆写；[旧版文档](UPGRADE-011.md)明确缺独立带标签准确率评估，居中伴奏也可能像人声。
- **方案／模块：**选入候选与 `unknown` 契约及手动选路；不把启发式置信度当概率，不按标签自动分离或调音。提高分类准确率及细分曲风质量阻塞，待带标签数据。`analysis.py`、`segments.py`、`service.py`、`interface.py`。
- **优先级／难度／风险／收益：**P0／中（拒判与选路）／整首误投人声链／保留用户控制、减少误处理。
- **验收：**对混合、反相、静音和争议素材能说明未知并显式改选；标称分类准确率须另有独立评测（G1）。

### 07. 人声能量分析
- **基线／问题：**全轨有 RMS、活动电平、LUFS；`service.prepare` 会另测已分离 Vocal，未分离时 `Vocal` 槽可引用原音，易混淆总量和人声量。
- **方案／模块：**选入按原音、人声、伴奏、总线标记口径；人声没有可确认来源则标未知。保留活动时间窗、响度门限和单位。`analysis.py`、`quality.py`、`service.py`、`studio_balance.py`。
- **优先级／难度／风险／收益：**P0／低／用伴奏抬高的人声电平设阈值／可靠地设定动态和混音起点。
- **验收：**同一 Vocal 配不同电平伴奏，人声报告保持对应原分轨；静音/无分轨不报伪 LUFS 或人声占比（G1/G2）。

### 08. 情绪和表达强度分析
- **基线／问题：**有高能量、响度、音高及起音变化等代理量，没有语义或情绪模型。设备增益和压缩会改变这些代理量。
- **方案／模块：**情绪识别质量阻塞；可沿用相对能量和瞬态作描述，不能推断情绪或表达意图，也不按情绪选预设。`analysis.py`、`segments.py`、`review.py`。
- **优先级／难度／风险／收益：**P2／高／误把较响等同于更有表现力／保留可复查的强弱变化而不误导。
- **验收：**本轮只输出测量、限制和未知；解阻须有多审听者标注、条件控制和留出集一致性报告。

### 09. 人声动态变化检测
- **基线／问题：**已有活动电平 10–90 百分位跨度、三秒短时响度及压缩衰减审计；静音和不足窗口时不能支持同样结论。
- **方案／模块：**选入共享独立 Vocal 的局部电平、动态跨度和处理前后衰减；区分真实动态与增益变化。`analysis.py`、`quality.py`、`engine.py`、`review.py`。
- **优先级／难度／风险／收益：**P1／低／短样本或全曲平均掩盖突发问题／少量压缩即可控制强弱差。
- **验收：**恒定与阶跃样本方向正确；不足三秒不伪造短时曲线，报告能定位过压或显著异常（G1/G2）。

### 10. 频段冲突分析
- **基线／问题：**`studio_balance.measure` 已估计两条已编排轨在同期活动窗的共享频带；能量重叠不等于耳听掩蔽或分离串音。
- **方案／模块：**选入复用测量及有界选频/宽带避让；无同时活动或无可用分轨不生成建议。`studio_balance.py`、`studio_effects.py`、`service.py`。
- **优先级／难度／风险／收益：**P0／中／误削有用伴奏或重复衰减／提高共存段人声可辨性。
- **验收：**同窗、同频带样本建议位置正确；错开时间、空轨或低证据不触发，旁通恢复、声道相位可复测（G2）。

## B · 分离、音频基础与导出（11–20）

### 11. 多模型人声分离
- **基线／问题：**仅 Spleeter 2-stem（两个 ONNX 图组成同一分离链，非两个可选模型）；模型约 11 kHz 有效带宽且可能串音，权重分发条款另审。
- **方案／模块：**多模型延期；选入复用固定哈希的 Spleeter、本地双轨及现有取消/回退。待有对照语料、许可证和资源预算再评估其他模型。`models_store.py`、`models_runtime.py`、`models.py`、`service.py`；见 [MODELS](MODELS.md)。
- **优先级／难度／风险／收益：**P0（复用），新模型 P2／中，扩展高／模型许可、内存与听感退化／使整曲工作流可离线完成。
- **验收：**本地权重可用时才推理；已有合格双轨不重复分离；缺失、损坏、取消走清晰提示且不提交半对分轨（G2）。

### 12. 分离质量检测
- **基线／问题：**模型文档记录形状、重建误差及有真值的个别 SDR；伴奏以残差生成，双轨重建好仍可能严重串音。
- **方案／模块：**选入长度、相位对齐、有限值、空轨、重建等完整性检查及独听提示。自动判断串音、边界伪影或「可用质量」阻塞于授权真值与盲听。`models_runtime.py`、`quality.py`、`tests/test_models.py`。
- **优先级／难度／风险／收益：**P0（完整性）／中，质量估计高／把恒等重建误报为分离纯净／防止坏轨进入母带。
- **验收：**异常轨可拒绝，受控重建可复现；有真值才报告 SDR 等质量指标，无真值不评级（G2/G4）。

### 13. 模型缓存
- **基线／问题：**`models_store` 已管理固定权重、临时下载、续传、校验、锁与迁移；推理生命周期与持久化分离结果是不同问题。
- **方案／模块：**沿用并回归权重缓存；从工程复用来源明确的双轨，不建通用推理结果缓存或常驻 GPU 池。若后续立项，按素材、模型版本和参数做失效键。`models_store.py`、`models_runtime.py`、`service.py`、`storage.py`。
- **优先级／难度／风险／收益：**P1／低（复用）／失效错误、缓存盘满或旧权重混用／避免重复下载与重复分离。
- **验收：**断网用已校验权重；损坏权重拒载；源文件更换不静默沿用旧分轨，清理不删除用户源文件（G2/G3）。

### 14. GPU 自动调度
- **基线／问题：**`providers` 已选择可用 CUDA/DirectML/CPU；DXGI 可检查适配器和预算，标准 Windows 分发为 DirectML/CPU。可枚举 provider 不代表真正执行了 GPU 算子。
- **方案／模块：**沿用回归，记录实际 provider、失败及回退；多任务 GPU 调度或新后端延期，不因本轮升级扩展硬件承诺。`models_runtime.py`、`models_dxgi.py`、`hardware.py`。
- **优先级／难度／风险／收益：**P1／中／误报加速、显存耗尽及驱动差异／可解释性能与故障。
- **验收：**模拟 provider 缺失与初始化失败、记录真正成功的路径；实测时附适配器和 provider，未测硬件不标通过（G2/G5）。

### 15. CPU 自动回退
- **基线／问题：**GPU 加载或执行报错可推进到下一 provider 并重算当前块；所有后端失败应中止，中途取消不是普通回退。
- **方案／模块：**沿用并把现有回退、子进程回收与取消接入整曲事务；不从头重复已完成块，也不改变已提交会话。`models_runtime.py`、`jobs.py`、`service.py`；见 [MODELS](MODELS.md)。
- **优先级／难度／风险／收益：**P0／中／死循环、块缺失或完成误报／GPU 故障时仍可能完成整曲。
- **验收：**注入运行中 GPU 失败并与纯 CPU 对照长度/重建；取消不启动下一 provider，双失败保留已有成品（G2/G3）。

### 16. 音频采样率统一管理
- **基线／问题：**`audioio` 统一到 44.1 kHz 双声道，保留原采样率、声道和位深；导出支持其他采样率，原文件元数据或编码结果不能与工作 PCM 混读。
- **方案／模块：**选入标明源/工作/输出口径；两轨共享同一采样时间轴，检查转换后对齐。保留原工作采样率及已支持的输出规格。`audioio.py`、`service.py`、`studio_session.py`。
- **优先级／难度／风险／收益：**P0／低／多次重采样、单声道双计或对齐漂移／统一时间窗与测量含义。
- **验收：**16 kHz 单声道及 48 kHz 立体声夹具转换后时间正确、元数据分别保留；成品回读不以工作率替代实际采样率（G2/G4）。

### 17. 音频设备热插拔
- **基线／问题：**`Player.poll_device` 能尝试恢复默认输出并保留播放位置；旧文档仍欠受控实体拔插证据。
- **方案／模块：**沿用模拟回归；实体矩阵受设备阻塞，暂停/重连策略不大改。`playback.py`、`hardware.py`、`studio.py`；见 [COMPATIBILITY-011](COMPATIBILITY-011.md)。
- **优先级／难度／风险／收益：**P1／中／驱动不回调或默认端点抖动／减少试听中断。
- **验收：**模拟断流恢复或安全暂停；解阻需实测多端点拔出/重接和默认设备切换，记录恢复时延及失败次数。

### 18. 低延迟试听
- **基线／问题：**PortAudio 读准备好的缓冲并统计欠载，支持同位置换缓冲和短交叉淡化；回调耗时不等于从操作到扬声器的时延。
- **方案／模块：**沿用离线缓冲试听和等响 A/B；低延迟目标延期，先建立实体回环与 P50/P95 测量，不在音频回调做推理或重渲染。`playback.py`、`interface.py`、`studio.py`。
- **优先级／难度／风险／收益：**P1／高／缩小缓冲可能爆音和欠载／改善调整反馈。
- **验收：**本轮回归播放、暂停、切换与欠载处理；后续按明确设备/缓冲统计端到端时延和稳定性后再声明低延迟。

### 19. 音频修复
- **基线／问题：**已有降噪、嗡声抑制、去齿和近满幅/平顶证据；原录音已削掉的信息不能由峰值保护复原。
- **方案／模块：**选入既有效果器的保守有界子集；真正去削波、去混响、风噪和宽带恢复延期且需听审。`engine.py`、`analysis.py`、`acoustics.py`、`quality.py`。
- **优先级／难度／风险／收益：**P1／中（复用）／水声、辅音损失或假修复／减少可确认的噪声与齿音。
- **验收：**已知噪声夹具在安静窗改善，正常段在旁通/无证据时不强修；削波只报告风险，不把输出较低峰值当恢复（G2/G4）。

### 20. 高质量导出
- **基线／问题：**已有 PyAV WAV/FLAC/MP3/AAC 导出、输出规格与临时文件非覆盖发布；导出窗口显示总线读数，编码成品需重新导入核对。
- **方案／模块：**选入保持格式与非覆盖语义、增加只读回读验收；区分总线和编码后的实际采样率、声道、时长、LUFS/真峰与近满幅计数。无损和有损分别验，不升级编解码器。`audioio.py`、`analysis.py`、`quality.py`、`dialogs.py`、`interface.py`；见 [MANUAL](MANUAL.md)。
- **优先级／难度／风险／收益：**P0／中／有损过冲、重采样或单声道折叠改变峰值／交付物可复核。
- **验收：**规格、音长与文件可解码性正确；无损用独立仪表对照并报告差值，有损复测超限则提示；取消/同名文件/编码异常不覆盖（G3/G4）。

## C · 自动化、多轨与可靠性（21–30）

### 21. 自动化音量曲线
- **基线／问题：**专业混音已有片段包络点、淡入淡出及保存；无独立自动生成的整轨音量曲线编辑层。
- **方案／模块：**沿用手动包络，整曲自适应采用有界常量推子及既有侧链；按活动窗自动写整轨节点延期。`studio_session.py`、`studio_timeline.py`、`studio_balance.py`。
- **优先级／难度／风险／收益：**P1／中／节点密集、开头与末尾跳变／平顺调整，保留人工细节。
- **验收：**手动包络、淡变和撤销重开一致；新建议不覆盖用户节点，测试非重叠段与片段边界（G3）。

### 22. 自动化效果器参数
- **基线／问题：**`segments.recommend_automation` 及效果器分段页已有平滑控制，覆盖 EQ、动态、去齿、降噪和空间等部分参数，不是任意插件参数自动化。
- **方案／模块：**选入复用有界参数，按可核验的人声证据或用户覆写应用；不为伴奏复制人声分段，不扩展任意参数图。`segments.py`、`engine.py`、`review.py`、`dsp_panel.py`。
- **优先级／难度／风险／收益：**P1／中／错误置信度和跳变引起抽吸或喀声／在不同发声段保留自然动态。
- **验收：**参数边界、平滑进出、旁通和保存重开稳定；混音未分离或无证据时不得自动套人声分段（G2/G3）。

### 23. 片段级效果链
- **基线／问题：**已有轨道/总线插入链及人声分段参数，不是每个片段有独立的可重排效果链与状态。
- **方案／模块：**延期。先复用轨道链；后续需设计片段 FX schema、跨片段滤波状态/尾部、重叠和旧工程兼容。`studio_session.py`、`studio_effects.py`、`studio_mix_dialogs.py`。
- **优先级／难度／风险／收益：**P2／高／效果尾部切断、预览与离线不一致／提高局部编辑自由度。
- **验收：**后续须测相邻与重叠片段、尾部边界和重开一致；本轮验证现有轨道与总线链不退化（G3）。

### 24. 实时预览优化
- **基线／问题：**多轨后台渲染、旧缓冲继续播放，新缓冲在原位置交叉淡化；长工程仍可能等待再次完整渲染。
- **方案／模块：**沿用背景作业与最后成功缓冲；增量分块预览和缓存策略延期，先用基准定位瓶颈。`studio.py`、`studio_session.py`、`playback.py`、`jobs.py`。
- **优先级／难度／风险／收益：**P1／高／旧任务晚到覆盖新参数或尾部状态不连续／长工程调整反馈更快。
- **验收：**快速连续改参、取消或关闭时不提交过期缓冲，预览所用方案与成品一致；性能声明需同工程前后计时（G3/G5）。

### 25. 多版本快照
- **基线／问题：**已有保存时 `.history` 备份、自动恢复文件和撤销/重做；没有命名、比较或分支式快照库。
- **方案／模块：**选入让可选处理方案进入既有备份和重定位；命名快照、快照比较 UI 和修订保留策略延期。`storage.py`、`interface.py`、`studio_session.py`。
- **优先级／难度／风险／收益：**P0（兼容）／中／备份中素材路径相对基准错误或方案丢失／可复现并安全回到旧状态。
- **验收：**覆盖保存、另存为、历史备份、恢复和重定位均保留有效方案；重复保存/重开不重复应用母带，不改变旧版本输出（G3）。

### 26. 人声与伴奏智能平衡
- **基线／问题：**工作站已有手动应用的重叠窗电平、避让、居中和响度匹配建议；一键调音之后的总线有峰值保护，但没有显式的完整歌曲自适应流程。
- **方案／模块：**选入分别测量、保守分轨 DSP、输入驱动的推子/避让和单次总线母带；优先解决实际冲突，不把固定预设当作测量，也不为了目标响度强推音量。`service.py`、`studio_balance.py`、`studio_effects.py`、`studio_session.py`、`engine.py`。
- **优先级／难度／风险／收益：**P0／高／双重增益、泵动、反相居中或压扁动态／完整歌曲可一键获得可解释的混音起点。
- **验收：**不同人声/伴奏比例产生方向及幅度合理的有界结果；反相不强制居中，空轨/错时不触发避让，真峰优先并报告响度差，保存重播一致（G2/G3）。

### 27. BPM 和节拍分析
- **基线／问题：**`analysis` 和 `acoustics` 按起音包络自相关给候选 BPM，缺可靠逐拍/下拍网格；倍频、半速和弱节拍语音有歧义。
- **方案／模块：**沿用并共享候选值及支持证据；正式节拍网格、速度曲线和自动同步延期。不确定时不自动锁定节拍。`analysis.py`、`acoustics.py`、`engine.py`。
- **优先级／难度／风险／收益：**P1／中／错速延迟或编辑点漂移／给手工节奏设置可靠提示。
- **验收：**定速点击轨有合理候选，稀疏语音、静音或节拍歧义标未知/不锁定；后续用带逐拍标注的素材验证网格（G1）。

### 28. 工程异常恢复
- **基线／问题：**已有会话退出标记、最近工程、自动恢复及原子 JSON；只保存已提交状态，不能恢复未完成的计算。
- **方案／模块：**选入保留最后成功工程，分离、处理和保存都在完整校验后提交；坏字段或缺素材可提示重定位，不改原文件。`app.py`、`health.py`、`interface.py`、`service.py`、`storage.py`；见 [0.3.2 修复](BUGFIX-2026-11-19.md)。
- **优先级／难度／风险／收益：**P0／中／无效数据进入恢复文件或误覆盖正常工程／取消、崩溃或磁盘故障后可继续。
- **验收：**模拟取消、保存失败、损坏项目和异常退出；恢复最后成功版本，正常关闭无误报，旧字段缺省正常工作（G3/G5）。

### 29. 长音频内存优化
- **基线／问题：**`audioio` 大文件使用临时映射，处理及多轨输出仍有整轨缓冲；同时保留原音、双轨和成品会放大峰值占用。
- **方案／模块：**本轮复用可用缓冲，避免无证据的重复整轨分析或分离，记录资源门槛；全链流式 DSP 和临时总线映射另排期。`audioio.py`、`service.py`、`models_runtime.py`、`studio_session.py`；见 [PERFORMANCE-011](PERFORMANCE-011.md)。
- **优先级／难度／风险／收益：**P1／高／内存峰值、临时盘占满、分块边界误差／长录音处理更可预期。
- **验收：**在明确的长音频测试规模下记录 RSS、临时盘、耗时与取消清理；不足以支持的规模安全失败，不声称全链恒定内存（G5）。

### 30. 多轨质量检测
- **基线／问题：**有轨道表计、相位相关、单声道折叠提示，`service` 检查成品帧数、有限性及峰值；缺整曲各阶段同口径的质量判断。
- **方案／模块：**选入分轨/总线输入输出校验与证据提示：错位、空轨、非有限值、折叠损失、响度/峰值冲突分开报；不计算主观质量。`quality.py`、`studio_balance.py`、`studio_session.py`、`service.py`、`review.py`。
- **优先级／难度／风险／收益：**P0／中／错位或超峰流入编码，正常空隙被误报为故障／在提交前发现结构性问题。
- **验收：**错长、NaN、强反相、叠加过冲及合法静音区各给正确拒绝/提醒；正常对齐项目正常渲染（G2/G3）。

- **方案／模块：**选入复用有界风格参数，整曲目标单独表达，允许显式自定义响度、峰值及处理倾向；已采用决定随工程持久化，不把素材路径或区间混入通用预设。`presets.py`、`engine.py`、`dialogs.py`、`storage.py`。
- **优先级／难度／风险／收益：**P1／中／越界值、重复母带或参数跨素材误用／保持偏好，可预测且可复现。
- **验收：**合法目标能改变对应有界决策；非有限及越界输入明确拒绝或按约定限幅；旧预设和旧工程行为不变（G2/G3）。

### 37. VST3 接口研究
- **基线／问题：**现有 Qt 离线工作站与内置 Python DSP，无 VST3 宿主或插件 ABI；[前期研究](RESEARCH-030.md)已列暂缓。
- **方案／模块：**延期，仅保留研究方向，先确认究竟是宿主还是插件，再评估许可、状态保存、进程隔离和实时线程预算；不引入第三方插件。潜在边界：`engine.py`、`studio_effects.py`、`playback.py`、`packaging/`。
- **优先级／难度／风险／收益：**P2／高／第三方原生崩溃、实时延迟与分发成本／可能扩展专业制作工具链。
- **验收：**不宣传 VST3 兼容；后续需独立宿主/插件原型及可复测的发现、装载、参数、崩溃隔离和延迟矩阵。

### 38. 本地 API 研究
- **基线／问题：**有离线 CLI/JSON 与内部 `service` 调用；[架构和平台文档](PLATFORMS.md)明确无公开上传服务或桌面网络 API。
- **方案／模块：**延期。优先以 CLI 满足脚本调用；如需本地 IPC，先设计版本、权限、路径校验、取消和并发，不在本轮监听端口。`cli.py`、`service.py`、`jobs.py`、`storage.py`。
- **优先级／难度／风险／收益：**P2／高／本地服务误暴露素材、跨任务覆盖输出／为受控的离线工作流预留自动化接口。
- **验收：**本轮无新增监听端口，CLI 兼容；未来需通过仅本机访问、访问控制、路径别名、并发写入与错误协议验证。
